# DocShift — локальное веб-приложение для миграции данных

Учебный проект для практики по базам данных. Работает в обычном браузере, полностью локально. Два режима: **SQLite → SQLite** и **папка → папка** с сохранением всех вложенных каталогов, в том числе пустых.

## Как скачать с GitHub и запустить в колледже

1. Откройте репозиторий [belyash67/DocShift](https://github.com/belyash67/DocShift) на компьютере колледжа. Нажмите **Code → Download ZIP** и дождитесь скачивания.
2. Распакуйте архив целиком в папку, доступную для записи, например в «Документы». Откройте распакованную папку `DocShift-main`, в которой лежат `app.py` и `start_windows.bat`. Не запускайте файлы прямо из ZIP.
3. Дважды щёлкните `start_windows.bat`. Дождитесь сообщения с адресом сайта и откройте этот адрес в Chrome или Edge. Обычно это `http://127.0.0.1:5000/`.
4. Пока работаете с программой, оставьте окно запуска открытым. Для остановки нажмите **Ctrl+C** в этом окне.

**Перед запуском проверьте Python:** на компьютере должен быть установлен Python **3.10 или новее**. Для проверки откройте терминал VS Code и выполните `py -3 --version` или `python --version`. Никакие `pip install`, `venv`, Flask и Docker не требуются. Интернет нужен для скачивания с GitHub; после распаковки приложение работает локально без интернета.

**Запуск через VS Code:** откройте распакованную папку `DocShift-main` через **Файл → Открыть папку**. Откройте `app.py` и нажмите **Run Python File ▶** либо используйте задачу **Ctrl+Shift+B**. F5 тоже работает при установленном расширении Python. Если браузер не открылся сам, возьмите адрес из терминала; при занятом порте 5000 приложение выберет следующий свободный. Права администратора не нужны.

**Если Python на компьютере вообще нет или его запуск заблокирован администратором, одна кнопка VS Code не поможет.** Тогда потребуется установленный Python или переносимая версия Python, разрешённая правилами колледжа. Сам проект не может запуститься без интерпретатора.

## Что входит

- `app.py` — **основной файл запуска**. Для обычной работы открывайте только его.
- `local_server.py` — локальный HTTP-сервер на стандартной библиотеке Python (вместо Flask, чтобы не устанавливать пакеты на учебных ПК).
- `migration/` — анализ базы, mapping, проверка записей, перенос, сохранение папок.
- `templates/`, `static/` — веб-интерфейс HTML/CSS/JavaScript.
- `vendor/` — Jinja2 и MarkupSafe (с текстами BSD-лицензий). Это чистый Python в составе проекта, поэтому интернет и `pip` не нужны.
- `legacy.db` — **готовая тестовая SQLite**: 500 документов, 40 пользователей, 8 отделов, из 500 документов 13 имеют намеренные ошибки.
- `samples/Папка_для_теста.zip` — исходная папка с **500 физическими документами**, `legacy.db` и вложенной структурой; распакуйте для ручной миграции папок.
- `create_test_database.py`, `create_test_folder.py` — генераторы тестовых данных.
- `tests/` — проверки миграции и настоящих HTTP-маршрутов.

## Демонстрация

В браузере: **Новая миграция → Использовать тестовую базу → Анализ → Mapping → Начать миграцию → Результат**. Система создаёт `cloud.db` для скачивания и журнал ошибок: из 548 строк успешно перенесено 535 (в том числе 487 документов), отклонено 13 документов. Первичные ключи создаются заново, старые номера сохраняются в `legacy_id`. Поля дат и статусов преобразуются, внешние ключи проверяются.

### Основной сценарий: перенос папки с документами

1. Создайте пустую папку назначения, например `Итоговые_данные`. Не выбирайте папку, где уже лежат файлы предыдущего переноса.
2. На странице «Новая миграция» выберите **исходную папку целиком** — например, `Пример_папки`, а не отдельный документ или файл `legacy.db`.
3. Выберите пустую папку назначения и нажмите «Начать перенос». В Chrome/Edge подтвердите доступ к папкам. Пока идёт перенос, не закрывайте вкладку.
4. На странице результата проверьте число файлов и каталогов, преобразование базы и список отклонённых записей. В выбранной папке будет то же дерево файлов; вместо `legacy.db` появится `cloud.db`. Исходная папка останется без изменений.

Если прямой выбор папок недоступен, раскройте «Перенести через ZIP» и загрузите архив исходной папки. Готовый ZIP скачивается на странице результата. Приложение не перезаписывает непустую папку назначения.

Для теста **папка → папка** используйте `samples/Папка_для_теста.zip`. Распакуйте архив, на странице «Новая миграция» в разделе «Исходная папка» нажмите «Выбрать папку» и укажите исходную папку целиком. Затем в разделе «Папка назначения» выберите **пустую** папку и нажмите «Начать перенос». В Chrome/Edge подтвердите разрешение на доступ к папкам. После переноса браузер сохранит в выбранную папку исходную структуру; `cloud.db` появится на месте `legacy.db`. Существующие файлы не перезаписываются. Если папка назначения не выбрана, сохраните результат на странице результата или скачайте ZIP. Можно также загрузить исходный ZIP без распаковки через «Перенести через ZIP»; в результате сохраняются даже пустые каталоги. Оригинальные файлы остаются неизменными.

Mapping — автоматическое сопоставление столбцов старой базы с новой. Например, `doc_id` становится `legacy_id`, `doc_name` — `title`, а `status_code` преобразуется из 0/1/2 в `draft`/`active`/`archived`. Некорректные строки отклоняются и попадают в журнал ошибок с причиной. `legacy_id` сохраняет связь с исходной записью, даже когда новый `id` отличается. После переноса приложение сверяет количество строк и внешние ключи, выполняет `PRAGMA integrity_check`; для папок также сверяет структуру, контрольные суммы файлов и пути документов. История запусков и ошибки хранятся в `database/app.db` и доступны после перезапуска.

Для генерации демонстрационных данных заново: `python create_test_database.py` обновляет учебный `legacy.db`, а `python create_test_folder.py --zip` обновляет ZIP в `samples/`. Команда `python create_test_folder.py` создаёт распакованную папку `Пример_папки` рядом с программой; не запускайте её повторно в папке с таким именем.

## Проверка

```bash
python -m unittest discover -s tests -v
```

Примеры SQL для результата:

```sql
SELECT COUNT(*) FROM documents; -- 487
SELECT COUNT(*) FROM users; -- 40
SELECT COUNT(*) FROM departments; -- 8
SELECT legacy_id, title, status, created_at FROM documents LIMIT 10;
SELECT id, legacy_id, title FROM documents LIMIT 10;
SELECT status, COUNT(*) FROM documents GROUP BY status;
PRAGMA foreign_key_check;
PRAGMA integrity_check;
```

## Если сайт недоступен

- Проверьте, **запустился ли `app.py`** и не закрыт ли терминал. `ERR_CONNECTION_REFUSED` означает, что по указанному адресу сервер не слушает порт.
- Откройте адрес, напечатанный в терминале: при занятом порте 5000 используется другой (например, 5001).
- Откройте обычный Chrome/Edge **на том же компьютере**. Адрес `127.0.0.1` не открывает сайт на другом устройстве или через удалённый браузер.
- Если видите `No Python`, `python was not found`, `Python not installed` — на компьютере нет доступного Python; попросите преподавателя указать уже установленный Python для VS Code.
- При ошибке пришлите **скриншот терминала VS Code**, где виден текст ошибки. Это полезнее, чем скриншот браузера.

## Архитектура и ограничения

Для простоты переносимости стандартный локальный сервер заменяет первоначальный Flask-приложение; **логика SQLite, структуры данных и интерфейс сохранены**. Всё хранится на вашем компьютере в `database/`. Исходная база не изменяется. Локальный сервер слушает **только `127.0.0.1`**, не публикует приложение в интернет. За один раз допустимо до 2500 файлов и 150 МБ при переносе папок. Рекомендуется распаковывать проект в пользовательскую папку, доступную для записи: программа сохраняет историю и результаты внутри `database/`.
