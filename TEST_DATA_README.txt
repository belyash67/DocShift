DocShift — демонстрационная база legacy.db
========================================

Это вымышленные учебные данные. Никаких реальных сотрудников или документов.

Содержимое:
  old_departments:  8 отделов
  old_users:       40 сотрудников
  old_documents:  500 документов за 2018–2025 гг.

В 13 документах специально есть ошибки:
  10, 205, 390  — пустое название;
  45, 245, 435 — неправильная дата;
  90, 280      — неизвестный пользователь;
  125, 315     — неизвестный отдел;
  160, 350, 480 — неизвестный код статуса.

Ожидаемый результат при выборе всех трёх таблиц в DocShift:
  Проверено строк: 548
  Успешно перенесено: 535 (487 документов + 40 сотрудников + 8 отделов)
  Ошибок: 13
  Целостность: OK

Как проверить:
1. DocShift -> Новая миграция -> Обзор -> выберите legacy.db.
2. Выберите old_departments, old_users, old_documents.
3. Посмотрите сопоставление полей (Mapping).
4. Запустите миграцию и откройте результат, ошибки и cloud.db.

Примеры запросов к legacy.db в SQLite Browser:
SELECT * FROM old_documents LIMIT 10;
SELECT * FROM old_users LIMIT 10;
SELECT * FROM old_departments;
SELECT * FROM old_documents WHERE doc_id IN (10,45,90,125,160);

Важно: поля file_path содержат только пути к условным файлам.
Реальные PDF к базе не прикреплены; DocShift переносит метаданные.

Чтобы заново создать legacy.db: python create_test_database.py
Не запускайте генератор в папке с пользовательской базой под именем legacy.db —
он перезаписывает учебный файл.
